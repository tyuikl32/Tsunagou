# FX-D01：资源占用明确释放，取消短时到期回收

日期：2026-09-28。确认依据：用户在修复设计访谈中选择 A。状态：**产品方向已确认，代码尚未实施**。

## 决策

1. 本机 Full Access 协作的资源写占用不设“若干秒没有续租即到期”的规则。正常推理、构建、等待工具、会话暂时沉默，不使任务失效，也不释放写占用供另一 Worker 使用。
2. 正常提交、明确挂起、取消完成等明确结束执行的动作释放占用；异常由主 Agent 判断并显式回收。Worker 不执行定时续租，运行层也不为这类占用增加心跳/保活系统。
3. 异常占用需要主 Agent 处置一次，不是把每次回收升级为用户审批。
4. 待领取、挂起、等待用户的任务持续存在。资源占用和任务的存在/可领取性不能重新混为一个计时器。
5. 本决策不取消后台 Job lease、HTTP 超时、票据有效期等各自已有的内部机制。
6. 保留身份、当前 owner、任务范围、版本与 execution/session/runtime 代次。资源回收只改变调度中心事实，不代表已经强制停止 Full Access 的物理文件写入。

## 取舍

接受 Worker 异常停止后需要主 Agent 显式处置这一成本，换取消除常规工作中的短时失效、续租和重复领取循环。主 Agent 在决定重新分派前处理原 Worker 是否仍在写、已写内容如何保留等业务问题；不新增机械“停止证明”审批系统。

## 与旧规范的关系

在本修复范围内，替换[资源模块](../implementation/modules/05-resources.md)的 120 秒 TTL、主动续租与自动到期回收，以及[旧队列决策](2026-09-21-task-queue-and-conversation-identity.md)中“资源 Lease 到期自动 orphan/open”的触发规则。旧文档在代码完成前保留为现状来源；修复时同步任务模块、恢复流程、协议、工具说明和回归。

断线或 daemon 重启也不能成为绕过明确回收的隐式资源释放路径；恢复仍须重新取得有效运行时授权，但不应仅因传输故障把原任务自动分派给其他 Worker。具体同 owner 恢复步骤在[修复方案](../implementation/live-test-repair-plan.md)中细化。
