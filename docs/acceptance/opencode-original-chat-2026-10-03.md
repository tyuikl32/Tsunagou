# OpenCode 原对话接入验收

日期：2026-10-03。宿主为本机 OpenCode 2.0.18。

## 实测结果

真实 OpenCode 会话引擎、已安装接入工具、Python CLI、daemon、stdio bridge 和控制台申请/状态服务完成隔离验收。模型响应使用本地可控 SSE 夹具；没有模拟宿主身份、CLI、MCP、登记或回执。

- 安装前创建原会话；实际执行 `agent prepare --adapter opencode`，重复执行配置不变，重载后返回相同会话。
- 从无关中文目录的原会话调用 `tsunagou_connect`，项目和 worker 角色来自控制台申请；目标项目路径也含中文和空格。
- 辅助 CLI 登记成功后控制台仍为 waiting；原会话原生 MCP 读取项目上下文后，精确回执与新鲜名单使其成为 arrived。
- 第二个真实会话无法认领原申请，也无法借用原会话的 Agent 身份。
- 重复接入及再次重载后，宿主 sessionID 和 Agent ID 均保持；接入过程没有改写宿主配置。
- 隔离宿主、daemon 与模型服务已停止；临时凭据、日志和一次性运行脚本已移至系统临时目录，不进入仓库。

## 验证边界

本次通过真实宿主服务 API 驱动原会话，验证控制台实际应用服务的等待/到达状态；没有声称完成人工浏览器点击或付费模型验收。首次重载后应等待 MCP 连接完成再调用工具：立即调用曾遇到宿主工具列表尚未加载，等待连接后通过。没有为此新增热加载或兼容层。

该结果覆盖新的本机原对话入口，不重报历史十一项共同基线，不包含自动唤醒。旧项目级入口与跨机器流程仍保留。

旧绑定检查读取所选项目及现有本机项目索引中的身份记录，不遍历磁盘。已从索引移除或移动后未重新登记的旧项目无法自动发现；这类旧会话应先处理原绑定，再使用新入口。新的共享路由始终拒绝跨项目覆盖。
