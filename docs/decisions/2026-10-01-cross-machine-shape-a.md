# D188 跨机器协作采用"主机 + 远端接入方"（形态 A）

日期：2026-10-01
状态：已确认，未实施

## 决定

跨机器协作采用**形态 A**：一台机器当"主机"，项目与 daemon 都在它上面；其余机器只作为"远端接入方"，
各自的 Agent（宿主窗口里的 bridge）直接连主机的 daemon。权威状态仍然只有一份，现有的一致性、幂等与
代次机制原封不动——对 daemon 来说，远端就是"多一个客户端"。

**排除形态 B**（每台机器各自一个 daemon，再让两个 daemon 互相同步状态）：它把"单写入"变成分布式一致性
问题（冲突、顺序、部分失败、双主），超出"让现有功能可以跨机器使用"的范围。

## 已接受的代价

- **主机是单点**：主机 daemon 不在，所有远端一起停；所以要接受"主机常开"。
- **远端叫不醒**：唤醒是本机机制，远端窗口只能常驻或轮询；跨机器时的常态是"远端发起、主机推动"。
- **远端需要自己的代码副本**（或只做非文件任务）；副本会漂移，必要时要把"哪一份是基线"显式化。
- **所有远端流量过主机**：主机的网络与磁盘成为共享资源。

网络层不自研：用现成的加密通道（WireGuard / Tailscale / SSH 端口转发 / 内网）让远端到达主机端口；
daemon 端口不暴露公网。
