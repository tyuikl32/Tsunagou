# FX-D03：原 Desktop 会话自动唤醒属于本轮必达范围

日期：2026-09-28。用户在明确了解 active writer 冲突后选择 A，保持原目标。

## 决策与验收

用户手动在 Codex Desktop 创建的会话，完成 Tsunagou 接入后，应由 daemon 的消息投递自动触发该原会话继续工作；不要求用户再发「继续」、操作重载或由本开发会话代发跟进。

原 thread 与新版 enrollment 获得的 agent_id 保持对应。替代 thread、替代 Worker、人工跟进、只能读取历史、只收到 callback 或 managed 路径通过，都不能替代这一项。全新状态验收与 FX-D02 一致，不要求延续升级前身份。

其他修复可以独立实施和验收，但该项未通过时，本轮总任务不能标记完成。当前实际宿主控制路径仍需技术核实；不能将「已创建研究任务」报告为功能交付。不得再以能力表或降级到手动收件箱关闭此缺口。

## 实施影响

- [修复总任务](../../.trellis/tasks/09-28-real-test-repair/prd.md)的 FX-R03 同时覆盖受控 Worker 与手动 Desktop 原会话。
- 接入、自动绑定、消息触发、宿主连接恢复、真实失败时间线必须形成一条可安装的产品路径。
- 继续复用现有 host wake port、持久收件箱及 outbox。实际控制接口的选择由技术研究解决；不再将该产品目标作为待用户决定项。
- 安装宿主侧接入适配器、配置 MCP 与启动/附着属于原接入授权。若最终路径要求改变用户创建会话方式或增设持续人工中继，属于目标变化，不能静默替换。
