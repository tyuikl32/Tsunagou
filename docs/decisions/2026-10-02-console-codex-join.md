# Codex 控制台接入：先保存申请，再由原聊天认领

日期：2026-10-02。来源：用户确认“前端已经唯一选定项目和身份，Codex 应只需一句话接入”，并授权实施。

## 问题

前端原流程先生成临时会话身份、签票并注册独立 MCP。真实 Codex Desktop 聊天具有不同身份，无法消费这份绑定。Agent 转而运行通用 prepare/connect 时，不继承前端项目和角色，可能从当前目录选错项目或采用默认 worker。要求用户在提示词里重复地址和角色只是在绕过断点。

## 决定

1. Codex 前端 prepare 只保存接入申请，返回 `host_registration.status=deferred`，不提前创建聊天身份、签票或登记独立 MCP。
2. 用户私有的 `~/.tsunagou/console-enrollments` 保存记录；同一 OS 用户跨控制台、跨项目只能有一个有效申请。`TSUNAGOU_ENROLLMENT_DIR` 可为测试隔离目录。记录按申请 ID 保留，不因下一次准备而覆盖查询对象。
3. `tsunagou agent join` 不需要项目或角色参数。项目和角色只取前端记录，聊天身份只取现有真实宿主发现与校验；短文件锁保护认领，不跨网络操作持锁。
4. 认领后只允许同一聊天重试，沿用已有身份；不因超时把已认领申请交给另一个聊天。无待接入申请明确失败，不初始化项目，不自动退回 worker。
5. 复用现有 connect 服务和共享 bridge。原聊天的成功 `context__project_read` 生成本次申请的私有回执；CLI bootstrap 辅助进程被明确排除。控制台同时核对精确 Agent/会话、角色、就绪状态和回执后才返回 arrived。
6. 未认领申请可过期或取消。已认领/登记申请取消返回 409；页面显示原因并继续等待，不能宣称已取消，更不能注销全局共享 MCP 或删除已接入身份。
7. 前端不改变 HTML/CSS；复用现有遮罩和提示，使用后端 `note` 显示进度。非 Codex 流程与显式 prepare/connect 入口保留。
8. `GET /console/enrollments/current` 返回当前申请的公共状态或 `none`。页面刷新后恢复该申请的等待/取消，始终标明原项目与角色；成功后只刷新相关项目数据，不恢复未知向导、不切换当前项目。相同项目/角色的 prepare 幂等复用原申请和昵称；不同选择的 409 带公共申请引用和下一步。prepare 先核对已完成回执，避免未轮询的旧申请长期占位。

## 验收与边界

程序回归覆盖不同工作目录、main/worker、并发认领、重复请求、取消/过期、重启记录、精确到达及 bootstrap 回执排除。前端回归覆盖 deferred 等待、各阶段说明、409 取消失败后继续等待、非 Codex 兼容。

这项能力限定本机同一用户，且已安装接入 Skill。共享 MCP 首次加载仍可能需要重开 Codex；测试进程成功不能证明原 Desktop 对话已加载工具。真实原对话验收须单独记录实际结果。

升级时已运行的旧版 bridge 进程不会自动执行新代码，也需要重载一次以支持回执；完成这次升级加载后，新增路由不要求重启。
