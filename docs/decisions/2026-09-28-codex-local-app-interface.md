# FX-D04：采用 Codex 应用本机接口实现原会话唤醒

日期：2026-09-28。用户在了解公开稳定性和维护成本后选择 A。对应 [FX-D03](2026-09-28-desktop-wake-required.md) 的实现依赖取舍。

## 决定

允许 Codex 专用宿主适配器使用桌面应用自带、但未公开承诺稳定的本机接口。当前优先实现已发现的 app tools 管道，沿应用自身向原 thread 发送跟进的路径触发回合。

宿主版本变化的适配集中在该 provider 内，其他七个模块及 A2A 消息协议不依赖管道细节。复用现有 HostWakePort、PrivateBindingStore、收件箱和投递去重，不建立通用宿主代理平台。

不要求保留原独立 listener 路径的 Desktop 自动唤醒兼容。managed app-server 仍服务其自身受控会话。允许接入时自动登记管道和原会话，不要求用户抄写 ID、endpoint 或令牌。

## 当前事实和实施界限

独立 Python tools/list 已成功；原会话发送、结束当前 Agent 回合后仍可调用、权限处理及宿主重启恢复尚未验收。研究及真实只读结果见[控制路径记录](../../.trellis/tasks/09-28-real-test-repair/research/codex-wake-control.md)。本决策不是声称功能已实现。

使用当前用户授权的项目绑定和真实调用上下文，遵守宿主自身权限/确认机制。不得通过假冒另一活跃回合、禁用校验或修改应用二进制来通过测试。若产品路径需要额外用户动作，必须具体查明该动作，不能让用户反复重启试错。

此决策替代旧宿主设计中“禁止使用 Desktop 私有 RPC”的限制；不改变原身份自动唤醒、用户专属动作、owner/scope 和真实失败留痕的要求。
