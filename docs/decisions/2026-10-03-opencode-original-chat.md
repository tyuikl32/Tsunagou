# OpenCode 本机接入使用当前真实对话

日期：2026-10-03。用户批准方案并要求最小工程量；首次安装允许重载一次并回到原对话。

本决定替代 [2026-10-02 控制台接入形态](2026-10-02-console-enroll-modes.md)中 OpenCode 本机申请预先指定会话名和签票的规则。旧申请、项目级手动接入和跨机器邀请不批量迁移。

1. 本机控制台只保存项目、角色、宿主与昵称，真实对话认领后才签票。工作目录不决定目标项目。
2. `agent prepare --adapter opencode` 一次性安装用户级无凭据工具和共享 MCP。后续接入只写私有会话路由。
3. 无参数工具 `tsunagou_connect` 从宿主上下文取 sessionID，调用固定已安装 CLI 的 `agent join --adapter opencode`；不接受模型指定身份、项目、角色或命令。
4. 复用现有申请存储、连接服务、私有路由和原会话回执。默认 Codex join 及 DSH 行为不变；不引入框架、新状态机或 daemon 权限。
5. 只认原会话真实 MCP context 的精确回执及新鲜名单。辅助登记成功不能显示到达；重试保留身份，其他会话不能接手。
6. 配置、旧绑定或跨项目冲突明示；不批量改用户配置、不静默创建第二身份。不加入自动唤醒、热加载或会话创建。

宿主接口以本机 2.0.18 实测为准，其目录插件使用 `setup(api)` 和 `api.tool.transform`，与上游 dev/v1 示例不同。预检证明工具上下文和原生 MCP 的 `ai.opencode/sessionID` 一致，重载后会话 ID 保持。预检采用真实宿主和本地测试模型响应，不等同于完整业务接入验收。
